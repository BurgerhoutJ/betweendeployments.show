<p>In the <a href="https://www.burgerhout.org/p/windows-365-wednesdays-understanding-cloud-pc-settings">previous part</a> of this series, we looked at managing Cloud PCs after they have been provisioned.</p>
<p>Now it’s time to make sure those Cloud PCs stay up to date.</p>
<p>If you are already using Windows Autopatch for your Windows endpoints, the good news is that Windows 365 Enterprise Cloud PCs are fully supported. There is no need to create a separate update management strategy just because these devices run in the cloud.</p>
<p>In this article, I will configure Windows Autopatch for Windows 365 Enterprise Cloud PCs.</p>
<h3>Enable Windows Autopatch for Windows 365</h3>
<p>The easiest way to enable Autopatch for new Cloud PCs is directly from the Windows 365 provisioning policy.</p>
<p>Open the Microsoft Intune admin center and navigate to:</p>
<p><strong>Devices → Windows 365 → Provisioning policies</strong></p>
<p>Create a new provisioning policy or edit an existing one.</p>
<p>During the provisioning policy configuration, you will find the <strong>Additional Services</strong> section.</p>
<p>Enable <strong>Windows Autopatch</strong> and select an existing Autopatch group.</p>
<p>This registers newly provisioned Cloud PCs with Windows Autopatch automatically.</p>

<p>Once the provisioning policy is assigned, every new Cloud PC created through this policy will automatically be registered with Windows Autopatch.</p>
<h3>What happens next?</h3>
<p>That’s it.</p>
<p>One of the nice things about the Windows 365 and Windows Autopatch integration is that there is no additional enrollment workflow required.</p>
<p>When a Cloud PC is provisioned, it will automatically appear in the Windows Autopatch experience and will follow the configured update management process.</p>
<p>From there, administrators can monitor:</p>
<ul>
<li><p>Update status</p></li>
<li><p>Deployment progress</p></li>
<li><p>Device health</p></li>
<li><p>Potential update issues</p></li>
</ul>
<h3>Checking your Cloud PCs in Windows Autopatch</h3>
<p>After the Cloud PC has been provisioned, it’s always worth verifying that everything is working as expected.</p>
<p>Under the <strong>Device</strong> → <strong>Overview</strong> section, select <strong>Autopatch management status</strong>. Open the Windows Autopatch section in the Intune admin center and check your Cloud PC devices.</p>
<p>Things to verify:</p>
<ul>
<li><p>Is the device registered?</p></li>
<li><p>Is the device up to date?</p></li>
<li><p>Are there any alerts?</p></li>
<li><p>Which types of updates?</p></li>
</ul>

<p>Windows Autopatch helps keep Windows devices updated by managing update deployment, monitoring health, and reducing the manual effort required from administrators.</p>
<h3>What about existing Cloud PCs?</h3>
<p>One thing to keep in mind: enabling Windows Autopatch in a provisioning policy is mainly intended for newly created Cloud PCs.</p>
<p>If you already have an existing Windows 365 environment, check the current registration status of your Cloud PCs before making changes.</p>
<p>Don’t assume that updating a provisioning policy will automatically update existing devices.</p>
<div class="callout-block" data-callout="true"><p>💡Keep your Windows 365 update strategy aligned with your physical Windows endpoints.</p></div>
<p>A Cloud PC is still a Windows endpoint.</p>
<p>Creating completely separate update processes for physical devices and Cloud PCs increases operational complexity and makes troubleshooting harder.</p>
<h3>Final thoughts</h3>
<p>There isn’t much configuration needed, and that is exactly the benefit.</p>
<p>Windows 365 Enterprise and Windows Autopatch are designed to work together. Enable the option in your provisioning policy, provision the Cloud PC, and let Autopatch handle the update management.</p>
<p>Simple, consistent, and aligned with a modern workplace approach.</p>
